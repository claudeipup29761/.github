<p>住宅 IP 资源管得乱，通常不是买少了，而是分配规则没写下来：谁在用哪条线、哪条线还能不能给别人、账号报废后出口要不要回收，全靠口头传。人一多就会长出两套隐形规则，一套在文档里，一套在聊天记录里。这篇给一份可以直接抄的分配清单，按项目、账号、成员三个维度切开，每一项都标注该谁拍板、留什么记录。</p>

<h2>一、先划项目边界，别按人头点 IP 数量</h2>
<p>"我们有八个人，是不是要买八条线"——这是最常见的起点，也是错的起点。资源应该按项目划，不按人头划。同一个人可能同时属于两个项目，共用一个出口比一人一条更容易踩到相互干扰。</p>
<h3>项目怎么切</h3>
<p>判断标准是"能否独立承担后果"。一个店铺、一组内容账号、一个 API 调用方，各自出问题不影响别人，就值得单独成一个项目。项目的边界一旦定下，后面所有的分配、审计、续费都以它为单位，不再拆细。</p>
<h3>每个项目先写三行字</h3>
<p>做什么、账号数量上限、谁是负责人。三行字写在共享文档的表格里，比任何制度文件都好用。没有负责人的项目不许开资源，这条规矩能省掉九成的扯皮。</p>

<h2>二、账号维度的取舍：独享、分组还是混用</h2>
<p>独享最贵但最好排查，共享最便宜但出事时互相牵连。中间的"分组共享"是多数团队实际会落到的位置，代价是要额外维护分组规则。</p>
<h3>三种模式的边界条件</h3>
<p>账号绑了付费订阅、或者需要长期保持登录态的，走独享；同一个人操作的三个小号、用途相近且互不登录的，可以同组；跨项目一律不许混用，这条没有例外。</p>
<h3>给出可以量化的判据</h3>
<p>一个账号一个月内触发验证超过五次，就说明它当前所处的共享程度过高，应该升级为独享。这个阈值不是标准答案，但比"感觉有点卡"可执行得多。</p>

<h2>三、成员维度：谁该拿到哪条线的凭据</h2>
<img src="/tp.png" alt="住宅 IP 资源在项目、账号、成员三个维度的分配结构">
<p>凭据扩散是资源管理里最难收回的一环。给得越方便，收得越困难。原则是：能用代管就不发原始密码，能临时授权就不给长期凭据。</p>
<h3>三种交付方式</h3>
<p>直接给账号密码最省事也最危险；通过内部代理网关转发，成员只拿到网关地址；用临时凭据加有效期，到期自动失效。团队规模超过五人，建议至少上第二种。</p>
<h3>离场流程要前置</h3>
<p>成员离开或换项目时，改密码、撤销白名单、回收凭据三件事必须在同一天完成。把这三步写进离场清单，比事后追查谁还在用要省力。</p>

<h2>四、权限与审计：三张表管住资源流向</h2>
<p>不需要复杂系统，三张表就能把资源管清楚：资源台账、分配记录、变更日志。表在哪儿不重要，重要的是有人维护、有固定更新频率。</p>

<h2>五、扩容与回收：什么信号出现时才动资源</h2>
<p>扩容要滞后于需求，回收要早于到期。前者避免浪费，后者避免为不用的东西续费。两个动作都要有触发条件，而不是等到有人喊。</p>
<h3>四个扩容信号</h3>
<p>账号数接近线路数上限、单条线一个月内验证次数持续上升、新增项目已立项、以及备用线启用频率变高。前两个是容量问题，后两个是结构问题，处理方式不同。</p>
<h3>回收的三个时点</h3>
<p>账号停用当天、项目结项当月、线路连续三十天无流量。第三个需要流量统计支撑，没有统计就靠人工每月抽查一次，别指望自动发现。</p>

<h2>六、上线前逐项打勾的一页纸</h2>
<p>清单的价值在于把判断变成动作。下面这些项目，全部能打勾再开资源，基本不会出现"这条线是谁在用什么都不知道"的局面。</p>
<h3>九个必查项</h3>
<p>项目有负责人吗；账号与线路是否一一对应；备用线是否验证过；凭据交付方式是否确定；台账是否已建行；到期日是否进日历；离场流程是否写明；扩容触发条件是否约定；审计由谁每月看一次。</p>
<h3>清单要能被新人读懂</h3>
<p>写完让一个没参与的人照着走一遍，卡住的地方就是需要补的地方。清单不是给自己看的备忘录，是给下一个接手的人看的说明书。</p>

<h2>常见问答</h2>
<h3>小团队只有三个人，也要建三张表吗？</h3>
<p>答：可以合并成一张，但字段不能少。资源台账和分配记录本质上是一张表的两列，人少时合起来更省事；变更日志即使只有一行字也要留，它是唯一能回溯"什么时候改坏了"的东西。</p>
<h3>项目之间能不能临时借一条线？</h3>
<p>答：技术上可以，管理上要在分配记录里写清借用起止时间，并在结束后把账号状态复位。不记录就借，等于给自己埋一个半年后才会爆的雷。</p>
<h3>IP 归属变化要不要通知使用人？</h3>
<p>答：要。出口属性变化会影响账号侧的判断，使用人必须知道什么时候变的、变成什么，否则出现异常时会把原因归错地方，白折腾一圈。</p>
<h3>没有专人管台账怎么办？</h3>
<p>答：把台账挂在每周例会的第一个议题，五分钟过一遍变更。固定节奏比专职岗位更容易长期维持，也更容易在人员变动时交接。</p>
